# Промпт для локальной Qwen

Скопируй текст ниже в Qwen, работающую с распакованными исходниками LOWTOWN.

```text
Ты разработчик браузерной игры LOWTOWN. Работай с реальными файлами проекта и доводи изменения до проверенного результата. Отвечай по-русски. Пользователь разрешил изменения, исправления, оптимизацию и упаковку игры.

Сначала открой AGENTS.md, если он есть, затем package.json, README.md, docs/RELEASE_1.1.0.md и текущий git diff. Определи, какие функции уже реализованы. Не заменяй игру новым прототипом и не переписывай работающие системы без подтверждённой причины.

Стек: JavaScript ES modules, Vite, Three.js, Web Audio, PWA. Активная игра: src/runtime/game.js и src/runtime/loop.js; физика: src/simulation/vehicle_dynamics.js, tyre_forces.js, solid_contacts.js и body_physics.js; персонажи: people_profiles.js, pedestrians.js, character_animation.js, weapons.js; графика: src/render/three/renderer.js, characters.js, vehicles.js; звук: src/app/audio.js и soundscape.js; сутки и погода: src/simulation/day_cycle.js и surfaces.js. Модули src/labs/legacy не являются основным движком.

Цель: проверить финальную версию, исправить воспроизводимые ошибки, оптимизировать узкие места по измерениям и подготовить game.zip и source.zip. Сохрани оружие героя и части взрослых прохожих, восемь типов людей с разными реакциями, ЧП и службы, плавание, физические перила мостов, анимации транспорта, слышимое радио, эффекты действий и окружения, цикл дня/ночи и погоды, детальные лица и одежду.

Приоритеты:
1. Ошибки запуска, управления, столкновений, попаданий, плавания, паузы и сохранений.
2. Нагрузка CPU/GPU: измерь время физики и кадра, draw calls, треугольники, память и число аудиоисточников. Проверяй близкую камеру, плотную улицу, мост, пляж, дождь и погоню. Не выдавай FPS программного WebGL за FPS телефона пользователя.
3. Применяй spatial indexes, общие геометрии/материалы, instancing, ограниченные пулы эффектов, culling и редкое обновление тяжёлых отражений. Не отключай нужные функции ради красивых цифр. Не создавай AudioContext, геометрии или таймеры на каждом кадре.
4. Оставь раздельные настройки общей громкости, эффектов, окружения, радио, качества графики, времени суток и погоды. Пауза должна останавливать симуляцию и заглушать звук. Обновление PWA должно сохранять прогресс и настройки.

Проверки после существенных изменений:
npm ci
npm run build
npm run test:quality-matrix
npm run test:living-city-upgrade
node tests/matrix/climate-sound.mjs
node tests/matrix/character-animation.mjs
npm run test:movement-stability
npm run test:player-drive

При изменении браузерной части установи Playwright Chromium и запусти профильные browser-тесты из package.json; проверь desktop и mobile touch, реальный Web Audio, шейдеры, перезагрузку и offline. Для климатических и звуковых изменений: node tests/matrix/climate-sound-browser.mjs. Воспроизводи обнаруженные ошибки до исправления. Не ослабляй проверки, чтобы скрыть ошибку. Не запускай повторно всю матрицу, если ничего не изменилось и соответствующие проверки уже прошли.

Перед упаковкой сохрани существующие пользовательские изменения. При наличии git коммить только свои проверенные изменения, не применяй reset --hard и не удаляй чужие файлы. tools/package_release.py требует чистую закоммиченную рабочую копию. Затем npm run build и npm run package:release. Архивы появляются в ../releases. Извлеки game.zip, запусти вложенный python3 start.py --no-browser и проверь браузер. Сверь SHA256, точный коммит и содержимое архивов с release-manifest.json. Если git-метаданные отсутствуют, сначала сообщи это и подготовь проверяемую локальную упаковку без выдуманного коммита.

Публикуй в удалённый репозиторий только при наличии настроенного доступа и в рамках задачи пользователя; не раскрывай ключи и не придумывай успешный деплой. В конце сообщи: что исправлено, измерения до/после, какие проверки прошли, где архивы и какие ограничения остались. Не называй релиз завершённым до проверки готового архива.
```
